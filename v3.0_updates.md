# OrbitalQuery v3.0 — Change Detection Engine Overhaul

> **Document Status:** Active  
> **Started:** September 3, 2026  
> **Branch:** feat/ui-coverage-and-change-regions

---

## Why v3.0?

The v2.x change detection engine used a **single-index threshold-based** approach:

```
NDVI_diff = NDVI_t2 - NDVI_t1
mask = |NDVI_diff| > threshold
```

This produced several problems visible in production:

1. **0 px / 0 km² results** — Thresholds too conservative; entire analyses reported no change despite visible landscape differences
2. **False positives** — No radiometric normalization between dates; atmospheric differences masqueraded as land surface change
3. **Single-index blindness** — Only NDVI was used, missing changes visible in other bands (e.g., urban expansion visible in SWIR)
4. **No change characterization** — Could not distinguish vegetation loss from water body change from urban growth
5. **No spatial context** — Pixel-level analysis produced salt-and-pepper noise instead of coherent change regions

v3.0 addresses all five issues with three new algorithms + a normalization pipeline, drawn from peer-reviewed remote sensing research.

## What Changed

### New Algorithm: Change Vector Analysis (CVA) + PIF Normalization

**File:** `analysis-service/app/services/cva.py`

**Problem it solves:** Single-index blindness + false positives from atmospheric noise

**How it works:**

1. **Pseudo-Invariant Feature (PIF) Normalization** — Identifies pixels that should not have changed between dates (water bodies, bare rock, dense urban) and uses them to compute a linear radiometric normalization. This removes systematic brightness/contrast differences caused by atmosphere, sun angle, and sensor calibration.

2. **Multi-band Change Vectors** — Instead of computing one index (NDVI), computes the change vector across ALL available bands simultaneously:
   ```python
   delta_vector = [B02_t2-B02_t1, B03_t2-B03_t1, B04_t2-B04_t1, B08_t2-B08_t1]
   magnitude = sqrt(sum(delta_vector**2))  # How much changed
   direction = atan2(delta_B08, delta_B04)  # What type of change
   ```

3. **Change direction classification** — The angle of the change vector reveals WHAT changed:
   - NIR decrease + Red increase → vegetation loss
   - NIR increase + Red decrease → vegetation gain
   - SWIR increase → urban expansion / soil exposure
   - SWIR decrease → water body expansion

**Key improvement:** CVA detects changes that single-index methods miss. A deforestation event shows NDVI decrease AND NIR decrease AND red increase simultaneously. CVA captures this multi-band signature.

**Papers:**
- Bovolo & Bruzzone, "A Theoretical Framework for Unsupervised Change Detection Based on Change Vector Analysis in the Polar Domain," *IEEE Trans. Geosci. Remote Sens.*, vol. 45, no. 1, pp. 218–236, 2007.
- Chen et al., "Land-Use/Land-Cover Change Detection Using Improved Change Vector Analysis," *IEEE Trans. Geosci. Remote Sens.*, 2003.

### New Algorithm: IR-MAD (Iteratively Reweighted Multivariate Alteration Detection)

**File:** `analysis-service/app/services/mad.py`

**Problem it solves:** Heuristic thresholding produces inconsistent results across different landscapes

**How it works:**

1. **Canonical Correlation Analysis (CCA)** — Transforms the multi-band difference into uncorrelated MAD variates that maximize the variance of spectral change.

2. **Chi-squared statistical test** — Instead of a fixed threshold (e.g., 0.12), uses a chi-squared distribution to determine which pixels show statistically significant change:
   ```python
   chi2_stat = sum((mad_variates / mad_std)**2)
   changed = chi2_stat > chi2_threshold(p=0.01)  # 99% confidence
   ```

3. **Iterative reweighting** — Outlier pixels (true changes) are down-weighted in successive iterations so the background statistics are not contaminated. This makes the method robust to mixed landscapes.

**Key improvement:** The threshold is derived from the data itself, not a human-tuned parameter. This means the same algorithm works for:
- Dense urban (Hyderabad) — high variance, needs permissive threshold
- Mangrove delta (Sundarbans) — water-dominated, needs conservative threshold
- Mountain terrain (Himalayas) — high elevation noise, needs robust statistics

**Papers:**
- Nielsen et al., "Multivariate Alteration Detection (MAD) and MAF Postprocessing in Multispectral, Bitemporal Image Data," *Remote Sens. Environ.*, vol. 64, pp. 1–19, 1998.
- Nielsen, "The Regularized Iteratively Reweighted MAD Method for Change Detection in Multi- and Hyperspectral Data," *IEEE Trans. Image Process.*, vol. 16, no. 2, pp. 463–478, 2007.

### New Algorithm: Object-Based Multi-Scale Change Detection

**File:** `analysis-service/app/services/object_cd.py`

**Problem it solves:** Salt-and-pepper noise + single-scale analysis

**How it works:**

1. **Multi-scale Gaussian analysis** — Computes change at multiple spatial scales simultaneously (10m, 20m, 40m, 80m) by applying Gaussian smoothing at different sigma values. Changes that persist across multiple scales are more likely to be real.

2. **Object-based classification** — Instead of classifying each pixel independently, groups neighboring pixels into coherent "change objects" using connected-component labeling at each scale, then applies a voting scheme across scales.

3. **Confidence scoring** — Each change pixel gets a confidence score based on how many scales detected it:
   ```python
   # Pixel detected at 1 scale = low confidence (0.25)
   # Pixel detected at 2 scales = medium confidence (0.50)
   # Pixel detected at 3+ scales = high confidence (0.75-1.0)
   ```

**Key improvement:** Eliminates the salt-and-pepper noise visible in the Sundarbans screenshot. Small isolated "change" pixels that appear at one scale but disappear at coarser scales are suppressed. Large coherent changes (deforestation patches, new buildings) that appear across all scales are emphasized.

**Papers:**
- Blaschke et al., "Object Based Image Analysis," *ISPRS J. Photogramm. Remote Sens.*, 2010.
- Chen et al., "Change Detection in Remote Sensing Images: Object-Based Image Analysis Approaches," *ISPRS Int. J. Geo-Inf.*, 2021.

### New Engine: Coverage-Aware EO Discovery

**File:** `analysis-service/app/services/discovery.py`

**Problem it solves:** Single-scene selection misses coverage gaps; no ranking by quality; no multi-scene support for large AOIs

**How it works:**

1. **NormalizedScene model** — Provider-agnostic scene representation. Every field comes from real STAC metadata or is None. Never fabricated.

2. **Coverage calculation** — Computes geometric intersection between each scene and the AOI. Also computes union coverage across multiple scenes and identifies uncovered portions.

3. **Multi-criteria ranking** — Scores each scene on 5 axes: AOI coverage (30%), cloud quality (25%), temporal fit (20%), band availability (15%), resolution (10%). Configurable weights.

4. **Period-aware selection** — For each time period, selects the best scene or optimal scene SET. When a single scene doesn't cover the full AOI, greedily expands coverage with additional scenes.

5. **DiscoverySummary** — Rich metadata for the UI: collection, provider, scene count, date range, best cloud cover, resolution, platform, composite status, uncovered portions.

**Key improvement:** Instead of `"Found 27 datasets"`, the UI can show:
```
Sentinel-2 L2A
23 observations
2021–2025
AOI coverage: 94%
Best cloud cover: 4.2%
Resolution: 10 m
```

### New Engine: Temporal Compositor + Analysis Grid

**File:** `analysis-service/app/services/compositor.py`

**Problem it solves:** Before/after images use different grids, resolutions, and extents — swipe mode shows misaligned pixels

**How it works:**

1. **AnalysisGrid** — Defines a common spatial grid: AOI bounds, CRS, resolution, pixel dimensions, affine transform. Both periods are resampled to this exact grid.

2. **Cloud masking** — Uses Sentinel-2 SCL (Scene Classification Layer) to identify and exclude cloud, cloud shadow, and cirrus pixels. Falls back to NDVI-based detection when SCL is unavailable.

3. **Temporal compositing** — From multiple observations per period, computes a cloud-free composite using median, mean, or first-quartile (Sentinel Hub recipe). Replaces single-cloudy-image with quality-filtered composite.

4. **Grid-aligned raster read** — Reads any raster into the common analysis grid using rasterio reprojection. Both before and after end up with identical bounds, CRS, resolution, and pixel dimensions.

**Key improvement:** Swipe mode now compares actual corresponding satellite pixels on the same grid. No geographic shift, no different extents, no basemap imagery mistaken for satellite data.

### Integration: Ensemble Change Detection

**File:** `analysis-service/app/services/temporal_compare.py` (modified)

All three algorithms run in parallel and their results are combined via an **ensemble voting scheme**:

```python
# Each algorithm votes on each pixel
cva_votes = cva_algorithm(bands_t1, bands_t2)       # magnitude + direction
mad_votes = mad_algorithm(bands_t1, bands_t2)        # statistical test
obj_votes = object_cd_algorithm(bands_t1, bands_t2)  # multi-scale consensus

# Combined: pixel is "changed" if ≥2 algorithms agree
ensemble_mask = (cva_votes + mad_votes + obj_votes) >= 2
```

This is more robust than any single algorithm:
- CVA catches multi-band changes that MAD might miss
- MAD catches statistically significant changes that CVA's threshold might miss
- Object-CD catches spatially coherent changes while suppressing noise

### New Engine: Unified Change Pipeline

**File:** `analysis-service/app/services/change_pipeline.py`

**Problem it solves:** Scattered change detection logic; no single entry point for the full bands→GeoJSON flow

**Architecture:**
```
BEFORE bands + AFTER bands
  → validity mask (cloud/nodata)
  → spectral indices (NDVI, NDBI, NDWI, NBR, NDSI, NDMI)
  → multi-signal evidence per phenomenon
  → spatial filtering (morphological + size)
  → connected components
  → change regions + statistics + GeoJSON
```

**Supported phenomena with multi-signal rules:**

| Phenomenon | Primary Index | Context Signal | Rule |
|-----------|--------------|----------------|------|
| Urban Expansion | NDBI ↑ | NDVI ↓ | Built-up gain + vegetation loss |
| Vegetation Change | NDVI ↓ or ↑ | — | Either direction |
| Water Change | NDWI ↓ or ↑ | — | Either direction |
| Burn Change | NBR ↓ | — | Fire damage |
| Snow Change | NDSI ↓ or ↑ | — | Either direction |

**Key principle:** Never interpret single-index change as ground truth. Multi-signal evidence + spatial consistency required.

### New Engine: Multi-Signal Evidence

**File:** `analysis-service/app/services/multi_signal.py`

**Problem it solves:** Single-index thresholds produce too many false positives; no way to combine supporting evidence

**How it works:**

1. **Per-signal evidence** — Each configured signal (e.g. NDBI increase) produces a binary evidence mask
2. **OR combination** — Alternative signals are combined with OR (e.g. vegetation loss OR gain)
3. **AND context** — Supporting signals are required with AND (e.g. NDBI↑ AND NDVI↓ for urban)
4. **Confidence scoring** — Per-pixel confidence = fraction of signals satisfied
5. **Direction classification** — Loss vs gain based on primary index delta direction
6. **Spatial filtering** — Morphological opening + minimum region size
7. **Region extraction** — Connected components with per-region statistics
8. **GeoJSON output** — FeatureCollection with bounding-box polygons per region

All thresholds configurable per phenomenon. No hard-coded universal threshold.

### New Engine: Imagery Preparation

**File:** `analysis-service/app/services/imagery_prep.py`

**Problem it sucks:** Raw satellite scenes contain clouds, shadows, haze, seasonal noise; comparing arbitrary dates produces misleading results

**Inspired by:** Sentinel Hub Custom Scripts (cloudless mosaics, temporal composites, forest-cut detection)

**Capabilities:**

1. **SCL Cloud Masking** — Uses Sentinel-2 Scene Classification Layer to exclude cloud/shadow/cirrus pixels. Falls back to NDVI-based heuristic when SCL unavailable.

2. **Outlier Detection** — Detects anomalous observations from cloud, shadow, snow, haze, and texture anomalies. Anomalous pixels never silently become change.

3. **Seasonal Windows** — Computes comparable seasonal periods for year-to-year analysis. Avoids comparing monsoon vs dry-season scenes.

4. **Cloud-Aware Compositing** — From multiple observations, computes quality-filtered composites using median or first-quartile (Sentinel Hub recipe). Replaces single-cloudy-image with cloud-free composite.

5. **NDVI Time Series** — Produces timestamp→NDVI for trend/monitoring queries. Used when query implies "over time", "trend", "seasonal", "monitoring".

6. **Visual Products** — True color, false color (vegetation), NDVI, NDWI, change mask, difference map. All with consistent legends and value ranges.

**Memory-safe:** All operations use numpy arrays already in memory. No new dependencies. Lazy scipy import.

## v3.2.1 Fix: Change Mask Stats Showing 0 km²

**Problem:** The change mask PNG was rendering correctly with visible red/green pixels on the map, but the statistics bar showed `0 px / 0 km²` for both loss and gain.

**Root cause:** Two issues in `TemporalComparisonView.tsx`:

1. **Nullish coalescing on `0`**: The code `changeVisStats.loss_area_km2 ?? fallback` never triggers the fallback because the backend returns `loss_area_km2: 0` (not `null`). JavaScript's `??` only falls back on `null`/`undefined`, not on `0`.

2. **Area disconnected from pixels**: Even when client-side pixel counting worked correctly, `lossKm2` was reading the backend's `0` value instead of computing from the counted pixels.

**Fix:**
- `lossKm2` and `gainKm2` are now always computed from actual pixel counts (`lossPixels * pixelAreaKm2`), never from backend area values
- Color detection thresholds widened to handle PNG compression artifacts: loss `R>140 && R>G+40 && R>B+40`, gain `G>100 && G>R+30 && G>B+20`
- Added loading state tracking for client-side fallback

**Why this matters:** The backend's old thresholds (`0.150`) were too conservative and returned 0 stats. The client-side fallback now correctly counts colored pixels from the mask PNG and computes area independently.

## Known Limitations

1. **PIF normalization** requires stable reference pixels. In landscapes with no stable features (e.g., rapidly changing urban areas), the normalization may be unreliable. Fallback: skip normalization if PIF correlation < 0.7.

2. **IR-MAD** assumes Gaussian distribution of spectral values. Highly non-Gaussian distributions (e.g., mixed urban/water) may produce suboptimal results. Fallback: use CVA's adaptive threshold instead.

3. **Object-CD** multi-scale analysis adds computational overhead (~2-3x vs single-scale). Mitigation: process at reduced resolution for initial detection, then refine at full resolution for change regions.

4. **Ensemble voting** requires ≥2/3 algorithms to agree. In rare cases where all three disagree on borderline pixels, the result may be conservative (missing some real change). This is intentional — false positives are worse than false negatives for this use case.
